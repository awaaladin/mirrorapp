# Mirror

Mirror is a native Android (Kotlin) AI-powered makeup simulation app. Users upload a
photo, Mirror detects facial landmarks fully on-device, and simulates makeup on the
photo — a digital makeup mirror for a still image, aimed at Nigerian women and makeup
artists, with a future live-camera "Pro" mode for business users.

## Tech stack

- Kotlin, Jetpack Compose (no XML layouts), Navigation Compose
- MVVM + Repository pattern, clean layering: `ui` / `domain` / `data`
- [MediaPipe Tasks Vision Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)
  for fully offline, on-device 468-point face mesh detection
- Firebase Authentication (email/password) for account sign-up/login
- `android.graphics` Canvas + BlendMode for makeup rendering (upcoming) — no
  RenderScript, no OpenGL
- Room, Coil, Retrofit/OkHttp, Paystack Android SDK (later phases — see Roadmap)

## Architecture

```
app/src/main/java/com/mirror/app/
  core/result/         AppResult<T> / AppError — typed success/failure used across layers
  domain/model/        Plain data classes: MakeupLook, ShadeItem, ClientProfile,
                        FaceLandmarkResult, AuthUser (no Android framework dependencies)
  domain/repository/   AuthRepository interface
  data/landmark/       FaceLandmarkerHelper — MediaPipe wrapper, on-device only
  data/auth/           FirebaseAuthRepository — real Firebase Auth-backed implementation
  ui/auth/             Login/SignUp screens + AuthViewModel
  ui/splash/           Branded calibration splash (in-app, Compose)
  ui/onboarding/       First-run walkthrough (shown once, after sign-up)
  ui/dashboard/        Looks tab / studio overview
  ui/editor/           Studio tab — real photo upload + on-device landmark detection,
                        shade/finish/intensity controls
  ui/beforeafter/      Interactive wipe comparator
  ui/clients/          Client consultation directory
  ui/settings/         Account info + sign out
  ui/navigation/       MirrorNavHost — auth-gated nav graph, bottom nav
  ui/theme/            Material3 theme built from the Mirror design kit tokens
```

**Local vs. cloud split:** face detection and makeup preview always run on-device via
MediaPipe and never make a network call. The *only* network dependency in the app is
Firebase Authentication (account sign-up/login). A future single-photo "cloud enhance"
action will go through a `CloudEnhanceRepository` interface, defaulting to a no-op
implementation that returns the local image unchanged.

## Requirements

- Android Studio Ladybug (2024.2.1) or newer
- JDK 17 (bundled with Android Studio)
- Android SDK Platform 35, minSdk 26
- A physical device or emulator running Android 8.0 (API 26) or newer (a real device is
  strongly recommended for MediaPipe performance testing)
- A free Firebase project (see below) — required for login/sign-up to work

## Setup

1. Clone/open this folder in Android Studio (`File > Open`, select `mirror/`).
2. Let Gradle sync. The project uses the Gradle wrapper (`gradlew` / `gradlew.bat`), so
   no local Gradle install is required.
3. Create `local.properties` in the project root if Android Studio doesn't generate it
   automatically:
   ```
   sdk.dir=/path/to/Android/Sdk
   ```
4. **Set up Firebase (required for login/sign-up)** — see below.
5. Run the `app` configuration on a device/emulator.

### Firebase setup (required — one-time, ~5 minutes)

The repo ships with `app/google-services.json` as a **placeholder** (syntactically valid
but with fake keys) purely so the project builds out of the box. Login/sign-up will fail
until you swap it for a real one:

1. Go to the [Firebase console](https://console.firebase.google.com/), create a free
   project (any name).
2. Add an Android app to it with package name `com.mirror.app`.
3. Download the generated `google-services.json` and replace
   `app/google-services.json` with it.
4. In the Firebase console, go to **Authentication → Sign-in method** and enable the
   **Email/Password** provider.
5. Rebuild and run — sign-up/login now work against your real Firebase project.

Everything else in the app (face detection, makeup preview, the shade catalog) stays
fully offline regardless of this step.

### Face Landmarker model asset

`app/src/main/assets/face_landmarker.task` (~3.7 MB) is committed directly since it's a
required runtime asset, not something generated by the build. If you ever need to
re-fetch it (e.g. to upgrade to a newer model revision), download it from:

```
https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/latest/face_landmarker.task
```

and place it at the same path.

## Testing

```
./gradlew test          # unit tests (ViewModel, and shade-repository logic once added)
./gradlew connectedCheck # instrumented tests, requires a connected device/emulator
```

## What to verify

1. Launch the app — you should see the branded calibration splash, then Login/Sign Up
   (or straight to the dashboard if already signed in).
2. Sign up with an email/password (needs the real Firebase config above and internet).
3. First-time sign-up shows the onboarding walkthrough once, then the dashboard.
4. From the dashboard, tap **Start Simulation** → **Choose a photo**. The app should
   detect ~468 face landmarks fully offline and show the shade/finish/intensity
   controls. Toggle **Show Mesh** to confirm the landmark dots track the face
   accurately. Try a photo with no face, or more than one face, and confirm you get a
   clear error message instead of a crash.
5. In Settings, **Sign Out** should return you to the Login screen.

## Roadmap

Real makeup rendering (Canvas BlendMode pixel work for lipstick/eyeshadow/etc — the
Editor's shade/finish/intensity controls are wired up but don't yet paint the photo),
the certified shade library as a swappable data source, Room-backed persistence for
saved looks and client profiles, gele/wig overlay, save/export, monetization (Paystack
one-time unlock + style packs behind `EntitlementRepository`), and Pro-mode feature
flags (live camera + cloud enhance, gated behind a subscription check that currently
always returns `false`).
